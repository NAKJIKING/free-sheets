## 2026-09-18 (이어받은 세션) — 크래시 복구 + 정답 라벨 버그 적발 + 학습 준비

### 가장 먼저 알아야 할 것 — 지난 세션 데이터의 정답이 2/3 틀려 있었다

`make_lib_lines.run_job` 이 매니페스트에 **조옮김 전** 음고를 썼다.
이미지와 렌더 미디는 LilyPond `transpose` 로 shift 만큼 옮겨져 있는데
정답만 안 옮겨져 있었다. 즉 **"D 로 그려진 음을 G 라고 답하라"** 고
가르치는 데이터였다. `--keys 3` 이라 shift != 0 인 줄이 약 2/3.

**왜 지난 세션이 못 잡았나**: 생성기 자체 대조가
`tokens + shift == 렌더미디` 로 비교한다. 라벨이 안 옮겨져 있어도
이 식은 성립하므로 "대조 불일치 0건" 으로 통과한다. 자기 검사가
자기 버그를 같이 틀린 전형적인 경우다.

실측(엘리제 altosax, shift=-5): manifest `[67,66,67,66,67,62]` /
렌더 미디 `[62,61,62,61,62,57]`.

고친 뒤 생성기를 다시 돌렸다(렌더는 전부 skip, 매니페스트만 재작성 —
13분). 그래서 **PNG/미디는 지난 세션 것 그대로 쓸 수 있었다.**

### 전처리 높이 160 → 224 (`prep.HEIGHT`)

실측: 음표 영역이 위아래로 잘린 줄이 **160 에서 4.67%, 192 에서 1.33%,
224 에서 0.17%**. 관문 기준이 NER 5% 인데 잘린 줄은 덧줄 개수를 셀 수
없어 음고가 **원리적으로** 안 읽힌다. GPU 비용은 +19% 뿐이었다.

어긋남 방지 장치 3개를 같이 넣었다(같은 부류의 버그가 재발하기 쉬운 곳):
- `model.py` 가 `prep.HEIGHT` 를 기본값으로 받는다 — 둘이 따로 놀 수 없다.
- 체크포인트에 `height` 를 적고 `evaluate.py` 가 다르면 **멈춘다**.
- `cache.py` 는 캐시 높이가 다르면 재개하지 않고 다시 굽는다.

### 학습 코드에서 고친 것 3건

1. **긴 줄을 이미지만 자르고 정답은 그대로 두던 것** — CTC 가 "이미지에
   없는 음표까지 읽으라" 고 배운다. 긴 줄은 `load_rows(max_w=)` 에서 뺀다.
   (실측 최대 폭 2129px 라 2600 문턱에 걸리는 줄은 실제로 0개다.)
2. **폭 정렬이 shuffle 로 무효가 되던 것** — `ThreadLoader(bucket=True)` 는
   표본이 아니라 **배치 차례**를 섞는다. 패딩 낭비가 준다.
3. **검증 표본** — 고정 간격으로 골라 에폭마다 같은 줄을 채점한다.
   폭 정렬 뒤 앞 N 배치만 보면 짧은 줄만 채점해 점수가 부풀려진다.
