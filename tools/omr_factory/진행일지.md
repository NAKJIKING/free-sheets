### 미디를 정답으로 써도 되는 이유 (실측)

연구문서의 "midi2ly 금지"는 **사람이 연주한** 미디에 대한 경고다. 라이브러리
미디는 abc2midi·MuseScore·LilyPond 가 찍은 것이라 격자에 정확히 붙어 있다.

| 항목 | 값 |
|---|---|
| 미디 파일 | 7,336 |
| 단선율 트랙 + 격자 정합 | **4,261곡 / 627,400음** |
| 16분 격자(Q=12 에서 3의 배수)에 든 음 | **91.3%** |
| 전음이 16분 격자인 곡 | 82.9% |
| 박자표 | 4/4 1771, 3/4 682, 6/8 571, 2/4 489, 9/8 101, 12/8 91, 2/2 90, 3/8 70, 3/2 57 … |
| 조표 | G 1037, D 806, C 685, Bb 281, F 272, A 208, Eb 204, Am 128 … |

**조 편중(다장조 80.6%)이라는 옛 약점이 사라졌다** — 라이브러리 조표가
이미 고르다. 특이 박자(3/2·9/8·12/8)도 들어 있는데, Audiveris 가 구조적으로
무너지던 바로 그 지점이다.

**정답이 어긋날 수 없는 구조**: 토큰 목록을 먼저 정하고 그것으로 `.ly` 를
써서 렌더하므로 이미지와 정답이 같은 원천이다. 그 위에 **LilyPond 가 같이 낸
미디를 다시 읽어 우리 토큰의 붙임줄 병합 음고열과 대조**한다(불일치면 그 줄을
버린다). `.ly` 작성 버그가 조용히 데이터에 섞이는 것을 막는 장치다.

**새 도구 (전부 이 폴더에 커밋)**
| 파일 | 하는 일 |
|---|---|
| `lib_lines.py` | 미디 → 단선율 멜로디 → 마디·토큰 → LilyPond 한 줄 조판. 최소 미디 파서 포함 |
| `make_lib_lines.py` | 위를 7,336개에 돌리는 실행기(재개형, 정답 대조 내장) |
| `prep.py` | **오선 정규화** — 오선 5줄을 찾아 줄간격 12px·높이 160 으로 맞춘다 |
| `cache.py` | 300DPI 렌더를 전처리해 학습용 회색 PNG 로 굽고 `index.jsonl` 생성 |
| `dataset.py` | 어휘·증강(순서 고정)·`ThreadLoader` |
| `model.py` | CRNN(5블록) + BiLSTM 2층 + CTC |
| `train.py` | 학습(재개 가능, 에폭마다 검증 NER) |
| `split.py` | **곡 단위** 학습/검증/시험 분할 |
| `evaluate.py` | 관문 1 판정 + 엘리제 예측·정답 미디 생성 |

**받아들이는 조건** (하나라도 어긋나면 그 청크를 버린다)
- 단선율 트랙(겹침 없음), 음 16개 이상
- 모든 온셋·길이가 16분 격자 → **셋잇단(4·8틱)은 이번 판에서 제외**
- 박자표가 실제 악보에 쓰는 것(`lib_lines.TIMESIGS`) — abc2midi 가 내는
  1/8·1/4·1/2 같은 퇴화 박자표는 8분음표마다 마디줄이 그어져 비현실
- 조옮김 결과 조표가 ±7 이내(`key_ok`) — 플랫 8개짜리 악보 방지

**이번에 잡은 결함 5건** (다음 세션이 같은 함정에 빠지지 않게)
1. 윈도우 LilyPond 는 `.mid` — `.midi` 만 찾으면 전부 실패로 센다.
2. `mido` 는 LilyPond 가 먼 조로 옮길 때 내는 조표(플랫 8개↑)에
   `KeySignatureError` 를 던진다 → **메타를 해석하지 않는 최소 미디 파서**로 교체.
3. **재개(skip) 할 때 정답 대조를 건너뛰면 안 된다** — 지난 실행에서
   불일치로 버린 파일이 다음 실행에서 조용히 통과해 데이터에 섞인다.
4. **검증셋이 비면 NER 0.0 이 나와 "최고 기록"으로 저장된다** → `None` 반환 + 경고.
5. **시험에서 어휘 밖 토큰이 있는 줄을 버리면 점수가 부풀려진다** →
   버리지 않고 −1 로 남겨 오류로 센다(`load_rows(keep_unk=True)`).
   그리고 같은 곡의 악기 판본 9개가 학습·시험에 갈라지지 않도록
   `song_key()` 가 악기 폴더를 떼고 묶는다.

**환경 함정**: 이 PC 의 실행 환경에서 **torch `DataLoader` 의 워커 프로세스가
`PermissionError: [WinError 5]`(큐 세마포어) 로 죽는다.** 그래서
`dataset.ThreadLoader`(스레드 기반)로 대체했다. `num_workers` 를 쓰는 코드를
다시 넣지 말 것.

### 다음에 할 일 (순서대로)

```bash
cd C:/Users/cocok/free-sheets
export LILYPOND='C:/Users/cocok/tools/lilypond-2.24.4/bin/lilypond.exe'

# 1) 생성 끝까지 (재개형 — 다시 돌려도 이어서 한다)
python tools/omr_factory/make_lib_lines.py --out C:/Users/cocok/omr_lines --keys 3 --max-chunks 6

# 2) 곡 단위 분할 (엘리제는 무조건 시험용)
python tools/omr_factory/split.py --data C:/Users/cocok/omr_lines

# 3) 전처리 캐시
python tools/omr_factory/cache.py --data C:/Users/cocok/omr_lines

# 4) 학습 (GPU)
python tools/omr_factory/train.py --data C:/Users/cocok/omr_lines \
    --out C:/Users/cocok/omr_model --epochs 40 --batch 16 --aug 0.35 --workers 8

# 5) 관문 1 판정 + 엘리제 증명물
python tools/omr_factory/evaluate.py --data C:/Users/cocok/omr_lines \
    --model C:/Users/cocok/omr_model --out C:/Users/cocok/omr_gate1
```

관문 1 = 시험용 곡(학습에 안 쓴 곡)의 깨끗한 렌더에서 **음표 NER 5% 이하**.
